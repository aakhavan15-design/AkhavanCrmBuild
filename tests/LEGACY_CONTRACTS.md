# وضعیت قراردادهای قدیمی در Closure Sprint

این فایل **گزارش ممیزی قراردادی** است، نه مجوز حذف تست شکست‌خورده.
در GitHub Actions، تست `npm run quality:ux` هنوز FAIL است. معیار DONE باید رفتار مالی، امنیت و کاربر را اندازه بگیرد، نه شکل نگارش سورس.

| آزمون | نوع | نتیجه بررسی هدفمند و اقدام |
|---|---|---|
| `documentationSetContracts.test.mjs` | Static/Regex تاریخی | دنبال عبارت‌های قدیمی `ui-ux-pro-max` و `F15` در چک‌لیست فعال می‌گردد؛ تاریخچه عمداً منتقل شده است. باید به آزمون وجود فایل‌های مرجع + صحت لینک آرشیو و شمارنده تغییر کند؛ تغییر مستند سالم برای PASS ممنوع |
| `customerListBalancePermission.test.mjs` | ترکیبی با یک انتظار غلط | مانده `c1=350` را با **سند فاقد وضعیت** قطعی می‌داند؛ طبق مصوبه جدید فقط POSTED/FINAL معتبرند و مقدار صحیح **۶۰۰** است. انتظار و پوشش تست باید تغییر کند؛ RBAC باید مستقل و رفتاری روی API آزمایش شود |
| `tourCoverageContracts.test.mjs` | ترکیبی؛ بعضی تست‌ها واقعی‌اند | منوی تور/مسیر را هم با `moduleForPath` می‌سنجد، هم DOM را با String جستجو می‌کند. شکست Selector متنی شاهد قطعی خرابی DOM نیست؛ آزمون مسیر/role و مرورگر لازم است |
| `persianLocalizationContracts.test.mjs` | Static/Regex | یافتن واژه انگلیسی در رشته فارسی می‌تواند نقص واقعی یا false-positive باشد؛ بدون یافتن متنِ واقعاً قابل مشاهده، متن سالم حذف نشود. بخش نمایش زبان با رندر واقعی بررسی شود |
| `ledgerJournalQuery.test.mjs` | ترکیبی؛ امنیت مهم | `parseJournalQuery` و `ledgerBalanceWindow` رفتار قابل آزمون دارند؛ Regex روی متن SQL ثابت، اثبات RBAC/RLS نیست. رد دسترسی در درخواست واقعی SQL/ERP برای VERIFIED لازم است |

**قانون اجرایی:** تست‌های فوق را کورکورانه Skip یا حذف نکن. ابتدا انتظار قدیمی را با معیار مصوب اصلاح کن، سپس Fixture عددی/HTTP/RBAC بساز. FAIL سراسری همچنان صادقانه حفظ شود؛ هیچ گیت تاریخچه‌ای به PASS جعل‌شده تبدیل نگردد.
