## ثبت اجرای F4-04 / F2-14 — کنترل نسخه و دامنهٔ وظیفه در API

- پنل گردش کار نسخهٔ رکورد را از DataProvider می‌گیرد. API هنگام ثبت، رکورد را در تراکنش قفل می‌کند، نسخه و انتقال را اعتبارسنجی می‌کند و نتیجه و ممیزی با شناسهٔ کاربر احرازشده با هم ثبت می‌شوند. درخواست قدیمی با `409` و امکان دریافت نسخهٔ تازه پاسخ داده می‌شود. ذخیرهٔ عمومی، بازنویسی گردش ثبت‌شده با نسخهٔ قدیمی یا دست‌کاری فیلدهای گردش را رد می‌کند.
- پنل هنگام ثبت تا دریافت نتیجهٔ درخواست باز می‌ماند تا پاسخ سرور به کارتابل برگردد. قرارداد پنل و Build گذشتند.
- Migration ۰۳۴ حوزهٔ وظیفه را از کاربر مسئول ثبت‌شده در دایرکتوری یا عضویت گروه معتبر SQL می‌گیرد. وظیفهٔ فاقد رابطهٔ معتبر به مجوز سازمانی نیاز دارد. خواندن و ویرایش عمومی وظیفه از همان قاعده استفاده می‌کنند.
- **شواهد** — Build، چهار فایل آزمون هدفمند و آزمون موبایل با پاسخ کنترل‌شده گذشتند. آزمون تراکنش کنترل‌شده، یک ثبت موفق در دو درخواست هم‌نسخه، رد رکورد خارج از حوزه و عدم تغییر در انتقال نامعتبر را پوشش داد. Migration و عضویت‌های دادهٔ واقعی `NOT VERIFIED - EXTERNAL DEPENDENCY` هستند. اتصال عملیات جانبیِ تغییر وضعیت به API گردش و آزمون زندهٔ دامنهٔ گروه و شعبه باز هستند.

- **شواهد** — Build، چهار فایل آزمون هدفمند و آزمون مرورگر موبایل با پاسخ کنترل‌شده گذشتند. Migration ۰۳۵، دادهٔ واقعی و پوشش پایش `NOT VERIFIED - EXTERNAL DEPENDENCY` هستند. این نما آخرین ۲۵ رکورد قابل مشاهده را نشان می‌دهد.
