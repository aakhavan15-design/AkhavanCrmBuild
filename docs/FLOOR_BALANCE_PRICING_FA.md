# تراز لحظه‌ای سفارش بر پایهٔ کلاس قیمت منتخب ERP

نسخهٔ این سند جایگزین بندهای متناقض «پیوست مشخصات موتور قیمت‌گذاری شناور v1.0» است.

## تصمیم‌های قطعی (اصلاح‌شدهٔ پیوست)
| موضوع | تصمیم |
| --- | --- |
| منبع قیمت | همهٔ قیمت‌ها و **کف** از ERP؛ CRM چیزی نمی‌سازد. کف معلوم است (پرسش باز ۲ پیوست بسته شد). |
| واحد پول | واحد پول/مقیاس قیمت از ERP خوانده می‌شود؛ کد پولی ثابت یا تبدیل خودکار فرض نمی‌شود. مقایسه فقط میان اقلام هم‌واحد مجاز است. |
| کلاس‌ها | پنج کلاس ثابت `PRICE_CLASS_1..5`؛ نام از ERP، وگرنه از «تعاریف پایه و داده ← نام کلاس‌های قیمت» (`/definitions`)؛ تنظیمات فقط سیاست‌هاست. کلاس ۵ بدون نام حدس‌زده نمی‌شود. |
| تراز | `(فی واردشده − قیمت همان کالا در کلاس منتخب) × تعداد پایه`؛ کلاس در سطح کل سفارش است و کد کلاس روی ردیف ذخیره نمی‌شود. |
| تعداد | کارتن × تعداد در کارتن = واحد پایه؛ تعداد در کارتن نامعلوم ⇒ ورودی به واحد و ۱ فرض نمی‌شود. |
| UI | تراز کل در نوار چسبان بالای اقلام و در خلاصهٔ مرحلهٔ ۳؛ ردیف سبز/قرمز + علامت و متن؛ محاسبه حین تایپ. |
| پیشنهاد | فی پیشنهادی (با تعداد فعلی) و کارتن پیشنهادی (با همین فی)، همزمان با هر تغییر؛ فقط Advisory و با دکمهٔ «اعمال». |
| ذخیره | تراز منفی یا کف نامعلوم ⇒ هشدار؛ ثبت ممکن است ولی خودکار «تأیید» نمی‌شود (`PENDING_APPROVAL`). |
| پالت | فقط Neo-Slate + Electric Indigo مطابق `docs/DESIGN_SYSTEM_FA.md`؛ فقط توکن معنایی (بدون hex). |

## قرارداد ورودی ERP برای کالا
`floorPrice`, `unitsPerCarton`, `priceClass1..5` (یا `priceClasses`)، اختیاری `priceClass1Label..5`، `currencyCode` دریافتی از ERP؛ نبود کد پول مانع محاسبهٔ تراز است.
مقدار صفر/منفی/اعشاری رد می‌شود (ETL: `PRODUCT_FLOOR_PRICE_INVALID` و …).

## محدودیت دقت عددی
موتور فعلی فقط مبلغ صحیح امن JavaScript را می‌پذیرد. دقت اعشاری و مقیاس مبلغ (ریال/تومان یا واحد دیگر) هنوز از قرارداد ERP تأیید نشده است؛ تا تعیین آن، این بخش برای تولید `NOT VERIFIED` است و نباید با گردکردن یا تبدیل ضمنی فعال شود.
