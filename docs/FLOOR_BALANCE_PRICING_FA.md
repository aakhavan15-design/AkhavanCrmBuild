# تراز لحظه‌ای سفارش بر پایهٔ پنج کلاس قیمت ERP

## قواعد قطعی
| موضوع | تصمیم |
| --- | --- |
| قیمت هر کالا | هر کالا پنج قیمت مستقل دارد؛ مقادیر کلاس‌های ۱ تا ۵ از ERP دریافت می‌شوند. نام هر کلاس از ERP یا تعاریف پایه قابل تنظیم است. |
| کلاس سفارش | کلاس انتخابی در سربرگ سفارش/پیشنهاد است؛ برای هر ردیف، قیمت همان کالا در همان کلاس خوانده و snapshot می‌شود. |
| مرجع/کف کلاس | قیمت همان کالا در کلاس منتخب، مرجع و کف همان کلاس است؛ فیلد مستقل floorPrice قدیمی صرفاً legacy است و در تراز استفاده نمی‌شود. |
| فی واردشده | فی واحد پایه است؛ فروشنده می‌تواند آن را پایین‌تر یا بالاتر از مرجع وارد کند؛ اختلاف تحلیل/هشدار است. |
| تراز ردیف | \((فی واردشده - قیمت کلاس همان کالا) \times تعداد واحد پایه\). |
| تراز سفارش | جمع تراز ردیف‌های معتبر؛ با تغییر تعداد یا فی، تراز ردیف و کل فوراً محاسبه می‌شوند. |
| تعداد | تعداد کارتن × تعداد در هر کارتن = تعداد واحد پایه. اگر ضریب بسته‌بندی نامعلوم باشد، حالت کارتن مسدود و ۱ فرض نمی‌شود. |
| واحد پول | تمام مبالغ داخلی ریال‌اند. کد صریح غیرریالی در ETL رد می‌شود؛ مقدار بدون کد طبق قرارداد پروژه ریال است. هیچ تبدیل ضمنی تومان/ارز دیگر انجام نمی‌شود. |
| پیشنهاد جبران | فی لازم با تعداد فعلی و تعداد/کارتن لازم با فی فعلی به‌صورت پویا محاسبه می‌شود؛ پیشنهادها فقط با اقدام کاربر اعمال می‌شوند. |
| تراز منفی | افزودن کالا با تراز منفی مجاز است؛ هنگام ذخیره هشدار می‌آید و تأیید خودکار انجام نمی‌شود. |
| خطاهای ورودی | تعداد، فی و حاصل‌ضرب‌ها باید عدد صحیح مثبت و در محدوده امن باشند؛ مقدار خالی/نامعتبر به صفر تبدیل نمی‌شود. |
| هویت بصری | فقط Neo-Slate / Electric Indigo و توکن‌های معنایی مصوب. |

## ورود سفارش ERP به CPQ
سفارش ERP واجد شرایط مذاکره باز می‌شود؛ مشتری و ردیف‌های سفارش به‌عنوان نقطه شروع پیشنهاد کپی می‌شوند. سفارش ERP اصلی دست‌نخورده می‌ماند. پیشنهاد CPQ یک موجودیت جداست و ذخیره آن به معنی ثبت سفارش یا فاکتور ERP نیست.

## دقت عددی
موتور تراز فقط مبلغ صحیح امن JavaScript را می‌پذیرد. دقت اعشاری باید با قرارداد ERP تأیید شود؛ تا آن زمان گردکردن یا تبدیل ضمنی ممنوع است.
